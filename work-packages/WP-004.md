### S1 — Provider Registry + Capability Profile + deterministic eligibility filter

**Status:** ACCEPTED

- Git-versioned Provider Registry: `config/provider-registry.json`
- Protocol: `owata.provider-registry/1`
- Static capability profile per binding (canonical `Capability` vocabulary)
- Pure eligibility API: ordered ELIGIBLE set or `NO_ELIGIBLE_BINDING`
- No active Dispatcher/Gateway cutover
- Local canary `model-policy` remains external (A-002)

### S2 — Normalized Availability Observation + availability overlay

**Status:** ACCEPTED

- Normalize structural `{ ok, authReady }` probes into `AVAILABLE` / `CREDENTIAL_UNAVAILABLE` / `AGENT_UNAVAILABLE` / `UNKNOWN`

- Distinct `NO_ELIGIBLE_BINDING` vs `NO_AVAILABLE_BINDING`
- Duplicate `binding_id` observations fail closed (`AVAILABILITY_INVALID`)
- Observations ephemeral; no SQLite; no dispatch selection / failover / cutover

### S3 — Deterministic Binding Selection

**Status:** ACCEPTED

- Pure `selectBinding(registry, request, observations)` → `SELECTED` | `NO_ELIGIBLE_BINDING` | `NO_AVAILABLE_BINDING`
- Composes `filterEligibleBindings` + `overlayAvailability`
- `SELECTED` = first AVAILABLE binding in exact S1 order (A-004)
- API + tests only; `ACTIVE_RUNTIME_CUTOVER=NO` (A-005)
- FailureClass mapping deferred (A-006); durable `binding_id` deferred until S4 (A-007)
- Gateway `adapter_id` ≠ registry `binding_id` (A-008)
