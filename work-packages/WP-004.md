## Scope

Phase 4 delivers a provider-neutral Model Router. This work package is **not** done until Program Control records `WP004_DONE=YES`.

### S1 — Provider Registry + Capability Profile + deterministic eligibility filter

**Status:** ACCEPTED

- Git-versioned Provider Registry: `config/provider-registry.json`
- Protocol: `owata.provider-registry/1`
- Static capability profile per binding (canonical `Capability` vocabulary)
- Pure eligibility API: ordered ELIGIBLE set or `NO_ELIGIBLE_BINDING`
- No active Dispatcher/Gateway cutover
- Local canary `model-policy` remains external (A-002)

### S2 — Normalized Availability Observation + availability overlay

**Status:** ACCEPTED

- Normalize structural `{ ok, authReady }` probes into `AVAILABLE` / `CREDENTIAL_UNAVAILABLE` / `AGENT_UNAVAILABLE` / `UNKNOWN`
- Overlay onto S1 eligible set; preserve S1 order; fail-closed on UNKNOWN
- Distinct `NO_ELIGIBLE_BINDING` vs `NO_AVAILABLE_BINDING`
- Duplicate `binding_id` observations fail closed (`AVAILABILITY_INVALID`)
- Observations ephemeral; no SQLite; no dispatch selection / failover / cutover

### S3 — Deterministic Binding Selection

**Status:** ACCEPTED

- Pure `selectBinding(registry, request, observations)` → `SELECTED` | `NO_ELIGIBLE_BINDING` | `NO_AVAILABLE_BINDING`
- Composes `filterEligibleBindings` + `overlayAvailability`
- `SELECTED` = first AVAILABLE binding in exact S1 order (A-004)
- API + tests only; `ACTIVE_RUNTIME_CUTOVER=NO` (A-005)
- FailureClass mapping deferred (A-006); durable `binding_id` deferred until S4 (A-007)
- Gateway `adapter_id` ≠ registry `binding_id` (A-008)

### S4 — Durable Binding Attribution

**Status:** ACCEPTED

Accepted capability:

- Schema v6: durable per-dispatch `binding_id TEXT NULL`
- Nullable backward-compatible attribution (`NULL` = no Router attribution)
- Optional `claimDispatch({ bindingId })`; empty string fail-closed
- `binding_id` distinct from Gateway `adapter_id`
- Per-attempt identity; lifecycle preserves attribution
- `cycle.dispatch_claimed` includes `binding_id`
- No active Router cutover; ordinary claims stay `binding_id=NULL`

### S5 — Routed Dispatcher Cutover

**Status:** ACCEPTED

**ACTIVE_RUNTIME_CUTOVER:** YES
**AUTOMATIC_FAILOVER:** NO

Accepted capability:

- Active routed Dispatcher cutover
- Explicit runtime catalog keyed by registry `binding_id`
- Durable selected binding attribution
- Routing block recovery (`cycle.routing_blocked`; A-009)
- Same-request binding pinning; no implicit failover
- Semantic new-request re-selection
- Program Control semantic authority preserved
- Schema remains v6; registry / model-policy unchanged

**A-009:** Pre-dispatch Router block is Router-native evidence + recovery; not a dispatch FailureClass.
