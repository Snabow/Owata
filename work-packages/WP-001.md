---

## Goal

Implement the smallest durable Control Core that guarantees:

> OWATA does not lose the identity or execution position of unfinished work when its process stops.

This WP establishes persistence, queue state, leasing, event evidence, and crash recovery.

It does **not** execute AI work.

---

## Success condition

> A forcibly terminated process can resume the same unfinished work from durable state.

---

## Scope

- Project state persistence
- Work state persistence (`QUEUED` | `RUNNING` | `COMPLETED`)
- SQLite (WAL, foreign keys, schema version, idempotent init)
- Atomic claim / lease / fencing token
- Expired-lease recovery (orphan detection)
- Event log in SQLite + append-only JSONL with crash-gap flush (SQLite authoritative)
- Process-interruption recovery integration test
- Preserve WP-000 CLI (`owata --version` / `doctor` / `status`)

---

## Required transitions

```text
QUEUED → RUNNING   (successful claim)
RUNNING → COMPLETED (valid current lease holder)
RUNNING → QUEUED   (lease expired + recovery)
```

Illegal transitions fail explicitly.

## Acceptance criteria (summary)

- SQLite state store under OWATA state directory with WAL
- Atomic claim; concurrent duplicate claim prevented
- Stale lease cannot complete; expired RUNNING recovered to QUEUED with same `work_id`
- Events in SQLite and JSONL; restart flushes pending JSONL without duplication
- Forced process-interruption integration test passes
- WP-000 tests remain green
- No WP-002 functionality
- Committed on implementation branch and pushed (not merged to `main`)
