## Goal

Implement the smallest single-worker execution loop that can take one durable OWATA work item from queue to verified completion without Human intervention.

```text
QUEUED → claim → execute → capture result → verify
  → if FAIL: bounded automatic repair → execute → verify
  → COMPLETED (only on verification PASS)
```

---

## Success condition

> One queued work item can be executed, fail verification at least once, be automatically repaired, and subsequently reach verified COMPLETED state without Human interaction.

Uses production worker-loop code and WP-001 durable Control Core.

---

## Scope

- Single worker claiming via WP-001 leases / fencing
- Durable execution spec (`task_type` + JSON input) on work items
- Durable attempt/result history
- Verification gate distinct from execution
- Bounded automatic repair (deterministic, no LLM)
- Crash/restart recovery using WP-001 lease recovery
- Deterministic local proving sample
- Event evidence extensions on existing SQLite + JSONL path

---

## Non-goals

- Any LLM / ChatGPT / Cursor / Codex / provider adapter
- Normalized cross-provider Work Package protocol
- Model Router / capability routing
- GitHub orchestration / Web UI / TFO / Phase 3

---

## Proving sample

Task type `sum_two`:

1. Attempt 1 executes with intentional defect → verification FAIL  
2. Automatic repair clears the defect in durable input  
3. Attempt 2 executes correctly → verification PASS → COMPLETED  

Repair must change the failing cause; it must not force the verifier to PASS.

---

## Acceptance criteria (summary)

- Verification PASS required for COMPLETED; execution success alone is insufficient
- Repair budget bounded; no infinite retry
- Real process-interruption recovery tested with same `work_id`
- Stale lease fencing remains effective
- WP-000 / WP-001 regressions remain green
- Branch committed and pushed (not merged)
